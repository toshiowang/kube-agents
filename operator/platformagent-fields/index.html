PlatformAgent fields

Every field of the PlatformAgent resource’s spec and status, generated from the operator’s Go API types. The standard Kubernetes apiVersion, kind and metadata are not listed. A field whose type comes from the Kubernetes API (corev1, metav1, networkingv1, resource.Quantity) names that type and is not expanded; the Kubernetes API reference describes it. Paths read parent.child, with [] for each item of a list and {} for each value of a map. Each description is the opening paragraph of the field’s documentation, plus its deprecation notice when it has one, and names other fields in their Go spelling (MaxSessions for maxSessions); kubectl explain platformagent.spec.<field> (platformagent.status.<field> for a row of the Status table) prints the whole text. The Constraints column lists the schema bounds on a field: allowed values, ranges, lengths and patterns. The API server also enforces CEL rules on these fields and on whole sections, which the column does not show; kubectl get crd platformagents.kubeagents.x-k8s.io -o yaml lists them under x-kubernetes-validations, each with the message the API server returns when a value breaks it. For what the fields do together, read the PlatformAgent CRD guide.

deployment.sidecarVolumes []corev1.Volume no SidecarVolumes specifies custom volumes to mount for the sidecar containers. An entry is refused at admission if it takes a reserved volume name, or if its source is one of the routes to the agent’s A2A bus credentials: a ServiceAccount token projection for the “a2a-bus” audience, or a reference to one of the Secrets the operator renders bus credentials into (<agent>-a2a-nats-creds, <agent>-a2a-nats-config, <agent>-a2a-callout-keys, <agent>-a2a-nats-tls, <agent>-a2a-nats-ca), as either a secret volume or a projected secret source. The refusal is on the name and the shape of the source, not on what a given Secret happens to hold at the time. Reading those Secrets through env is not refused here. On an install running the A2A surface the same entries are dropped from the render as well, which is the half that holds when admission does not run: a default chart install does not register the webhooks at all (operator.webhooks.enabled=false), and one that does registers them at failurePolicy Ignore by default.
deployment.extraVolumes []corev1.Volume no ExtraVolumes specifies custom volumes to mount for the main container. The same reserved names and reserved sources as SidecarVolumes are refused at admission – a ServiceAccount token projection for the “a2a-bus” audience, or a reference to <agent>-a2a-nats-creds, <agent>-a2a-nats-config, <agent>-a2a-callout-keys, <agent>-a2a-nats-tls or <agent>-a2a-nats-ca – and dropped from the render on an install running the A2A surface.
deployment.extraVolumeMounts []corev1.VolumeMount no ExtraVolumeMounts specifies custom volume mounts for the main container. Appended to platform-agent and platform-agent-dashboard both, so an entry naming a reserved volume is refused at admission, and dropped from the render on an install running the A2A surface. deployment.availability object no Availability configures high availability and scheduling settings for the agent pod.

A multi-replica gateway does not start yet, because its leader election has no in-cluster ServiceAccount token to use and the data volumes an install creates at one replica are ReadWriteOnce.

deployment.resources corev1.ResourceRequirements no Resources specifies resource requests and limits for the main container.
deployment.credentialProxy object no CredentialProxy configures the credential-proxy container, the broker that runs every credentialed command on the agent’s behalf in a pod of its own.
deployment.credentialProxy.resources corev1.ResourceRequirements no Resources overrides the credential-proxy container’s requests and limits. Each key set here replaces the operator’s default for that key and the rest keep their defaults, unlike spec.deployment.resources, which replaces the agent container’s block wholesale: a CR that sets only limits.memory keeps the default 500m CPU request, 1 CPU limit and 2Gi ephemeral-storage limit. The broker sizes how many commands it admits at once from the memory limit, so raising the limit is the one knob for an install whose fleet outgrows the default; the ephemeral-storage limit bounds the content workspace the broker clones into; the proxy’s state and /tmp emptyDirs (sizeLimits 5Gi and 2Gi) follow it when it is raised above their defaults, so the kubelet does not evict the pod at the smaller figure. Only cpu, memory and ephemeral-storage are accepted, the quantities the container declares. The operator refuses a memory limit below what admits two commands at once, a limits entry set alone below the default request it would cross, a request above its limit, a negative quantity and a zero limit; claims is refused, because the proxy pod declares no resourceClaims. A refused override, including an edit of one that was valid, renders the proxy Deployment at the operator’s defaults, not at the last accepted override, until it is corrected, which on the proxy’s Recreate Deployment restarts the proxy once; the operator reports Degraded with reason InvalidCredentialProxyResources when no higher-ranked Degraded cause is present, the agent staying Ready, whether or not the validating webhook is enabled. Where the webhook is on, it refuses the edit at apply and the running proxy is untouched. The webhook warns when memory per CPU on the requests pair leaves the band GKE Autopilot admits unchanged, because Autopilot then raises the smaller request into the band; it applies the band to requests only. It also warns for each of cpu and memory set under limits without the same key under requests, unless the limit equals the request it would be replaced by: Autopilot without bursting sets the limits equal to the requests, so there the proxy runs at the request and the limit has no effect. With bursting the declared limits stand.
deployment.agentAPIAuth object no AgentAPIAuth configures the agent-api-auth sidecar in the gateway pod, the native container that authenticates the agent’s API-server calls and also runs the event watcher and the drift detector.
deployment.agentAPIAuth.resources corev1.ResourceRequirements no Resources overrides the agent-api-auth container’s requests and limits. Each key set here replaces the operator’s default for that key and the rest keep their defaults, unlike spec.deployment.resources, which replaces the agent container’s block wholesale: a CR that sets only limits.memory keeps the default 150m CPU request, 384Mi memory request, 1 CPU limit and 2Gi ephemeral-storage limit. The container runs the event watcher, the drift detector and the API authenticator together; the event watcher reads the memory limit through the Downward API and sets its Go soft memory limit to half of it, so raising the memory limit is the knob for an install whose fleet of watched clusters outgrows the 2Gi default. Only cpu, memory and ephemeral-storage are accepted, the quantities the container declares. The operator refuses a request above its limit, a negative quantity, a zero limit, an unrepresentable byte or CPU count and claims, because the gateway pod declares no resourceClaims. A refused override, including an edit of one that was valid, renders the sidecar at the operator’s defaults until it is corrected, and the operator reports Degraded with reason InvalidAgentAPIAuthResources when no higher-ranked Degraded cause is present, the agent staying Ready, whether or not the validating webhook is enabled. Where the webhook is on, it refuses the edit at apply. The webhook warns when memory per CPU on the requests pair leaves the band GKE Autopilot admits unchanged, and when a cpu or memory limit is set without the same key under requests, for the reasons the credential-proxy field documents.

The credential broker mints a short-lived token for the account a request’s project maps to, instead of using the agent’s own identity — which, holding a project-level roles/container.viewer, can read objects in every cluster in the project.
security.scopedServiceAccountPool.enabled boolean no false Enabled arms the credential broker: with it true, every cluster read is made as the account its project maps to, and a project with no entry is refused. Default false, and it should stay false until the pool’s accounts hold authority.

security.scopedServiceAccountPool.serviceAccounts[].serviceAccountEmail string yes pattern ^[a-z][a-z0-9-]{4,28}[a-z0-9]@[a-z0-9-]{6,30}\.iam\.gserviceaccount\.com$ ServiceAccountEmail is the account scoped to this project. It lives in the host project, whatever project it reads; Terraform’s scoped_service_accounts output is the source of these values.
security.workloadIdentityFederation object no WorkloadIdentityFederation gives the credential proxy a GCP identity that does not come from the metadata server.

security.workloadIdentityFederation.serviceAccountEmail string no max length 256 ServiceAccountEmail is the GSA the federated principal impersonates.

security.egressAllowlist object no EgressAllowlist tunes the destinations egressPolicy: Allowlist permits. Ignored for any other egressPolicy value.
security.egressAllowlist.controlPlaneCIDRs []string no ControlPlaneCIDRs are the address ranges of the Kubernetes API server, permitted on port 443.
security.egressAllowlist.extraRules []networkingv1.NetworkPolicyEgressRule no ExtraRules are appended verbatim to the rendered policy, for destinations a plugin or a custom sidecar needs.
telemetry object no Telemetry configures OpenTelemetry export for this agent.
telemetry.otlpEndpoint string no max length 2048; pattern ^$|^https?://[^\s]+$ OTLPEndpoint is the base URL of an OTLP/HTTP collector, for example “http://otel-collector.otel-collector.svc.cluster.local:4318”. Give the base URL only — the per-signal path (“/v1/traces”) is appended by the exporter.
networkPolicy object no NetworkPolicy configures the operator-generated egress NetworkPolicy.
networkPolicy.enabled boolean no Enabled turns operator-managed NetworkPolicy generation off entirely, for installs that manage network policy through their own tooling. Unset means on.
networkPolicy.dnsClusterIPs []string no max items 8; items max length 45; items pattern ^((((25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])\.){3}(25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9]))|(([0-9a-fA-F]{0,4}:){1,7}[0-9a-fA-F]{0,4}))$ DNSClusterIPs pins the cluster DNS Service ClusterIPs. Setting it disables discovery, like spec.telemetry.otlpEndpoint. Each entry is a bare IP with no prefix; the operator writes it into rule 1 as a /32 or /128.
networkPolicy.metadataDaemon object no MetadataDaemon describes the node-local cloud metadata daemon. Leave nil to let the operator discover the container port from the kube-system/gke-metadata-server DaemonSet (falling back to port 988 and 169.254.169.252). Overriding the endpoint via annotation, spec, or operator flag opts out of discovery and uses port 988. Present with Endpoint “” emits no post-NAT rule at all, for datapaths that evaluate pre-NAT or clouds without one.
networkPolicy.metadataDaemon.endpoint string yes pattern ^($|(((25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])\.){3}(25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9]))|(([0-9a-fA-F]{0,4}:){1,7}[0-9a-fA-F]{0,4}))$; max length 45 Endpoint is the daemon IP. “” (explicitly set) suppresses that rule entirely; the empty alternative in the pattern is required because the API server validates an explicitly-set “”, which omitempty does not suppress.
networkPolicy.additionalEgress []object no max items 32 AdditionalEgress appends CIDR-and-port egress rules to the generated policy. Entries are not passed through untouched: every peer CIDR is canonicalised, and three things the schema below cannot express are dropped by the operator instead – an IPv4-mapped IPv6 peer, which clears the IPv6 prefix floor and then fails the IPv4 one once collapsed to the block it means; an except that is not a strict subset of its peer, which the API server would reject the whole policy for; and a rule left with no usable peer, which would otherwise permit egress to every destination. Each drop is logged and costs only the entry it names. Everything else is rejected at admission – except an entry with no ports, which is admitted and opens every port to its peers. See EgressRule.ports.
networkPolicy.additionalEgress[].to []object yes min items 1; max items 16 EgressPeer defines a CIDR block and optional exclusions.
networkPolicy.additionalEgress[].to[].cidr string yes min length 1; max length 49; pattern ^((((25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])\.){3}(25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])(/(1[2-9]|2[0-9]|3[0-2]))?)|(([0-9a-fA-F]{0,4}:){1,7}[0-9a-fA-F]{0,4}(/(4[89]|[5-9][0-9]|1[01][0-9]|12[0-8]))?))$ CIDR is an IPv4/IPv6 block or host IP, e.g. 10.0.0.0/24 or 10.0.0.1.
networkPolicy.additionalEgress[].to[].except []string no max items 16; items max length 49; items pattern ^((((25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])\.){3}(25[0-5]|2[0-4][0-9]|1[0-9][0-9]|[1-9]?[0-9])(/([0-9]|[12][0-9]|3[0-2]))?)|(([0-9a-fA-F]{0,4}:){1,7}[0-9a-fA-F]{0,4}(/([0-9]|[1-9][0-9]|1[01][0-9]|12[0-8]))?))$ Except carves ranges out of CIDR. Each entry must be a strict subset of CIDR – contained by it and narrower than it – because ValidateIPBlock rejects the whole NetworkPolicy otherwise, which would freeze every other egress rule at its previous revision. The resolver applies the same test and drops an except that fails it rather than forwarding it.
networkPolicy.additionalEgress[].ports []object no max items 16 Ports restricts the rule to these destination ports. Omitting it emits a rule with peers and no ports, which in NetworkPolicy semantics permits EVERY port to those peers – the mirror of the case the operator refuses to emit, a rule with ports and no surviving peer. That is standard NetworkPolicy behaviour and a legitimate thing to ask for, so it is admitted rather than blocked and nothing is logged; list the ports if you did not mean it.
networkPolicy.additionalEgress[].ports[].protocol string yes one of TCP, UDP, SCTP
networkPolicy.additionalEgress[].ports[].port integer yes min 1; max 65535
harness object yes Harness configures the core execution environment and framework-level settings.
harness.clusterName string yes ClusterName is the logical name of the cluster (either where the agent is running or the target cluster).
harness.location string yes Location is the geographical location or cloud region.
harness.projectId string yes ProjectID is the GCP Project ID of the cluster. Required alongside ClusterName and Location: the credential proxy only renders its bootstrap (the gcloud container clusters get-credentials that gives the agent a usable kubectl context) when all three are set. Omitting it leaves every kubectl call in the sidecar pointed at localhost:8080. See buildCredentialProxyEnv.
harness.hermes object no Hermes configures the internal event-routing or agent framework.
harness.hermes.dashboardEnabled boolean no true DashboardEnabled toggles the AGENT_DASHBOARD environment variable.
harness.hermes.pluginsDebug boolean no false PluginsDebug toggles the AGENT_PLUGINS_DEBUG environment variable.
harness.hermes.agentHome string no /opt/data AgentHome is the path to the AGENT_HOME directory.
harness.hermes.apiServerSecretRef corev1.SecretKeySelector no ApiServerSecretRef references the Secret key holding API_SERVER_EXTERNAL_KEY, the credential outside callers present to the credential-proxy sidecar. It does not set API_SERVER_KEY: the value the Hermes API server itself validates is the non-secret loopback sentinel cluster-internal-trusted, a compile-time constant the sidecar swaps in once it has authenticated the caller.
harness.hermes.sessionKVApiKeySecretRef corev1.SecretKeySelector no SessionKVApiKeySecretRef references the Secret key holding the bearer token for the pod-local Session KV server on port 8699. Distinct from API_SERVER_KEY, which is that loopback sentinel and would authenticate nothing here.
harness.hermes.sessionKVSaltSecretRef corev1.SecretKeySelector no SessionKVSaltSecretRef references the Secret key holding the HMAC salt used to pseudonymise chat identities before they reach session metadata, audit logs, or OTel spans. When absent the agent generates a per-pod salt and logs a warning: hashes then stop correlating across restarts.
harness.memory object no Memory configures agent memory settings.
harness.memory.memoryEnabled boolean no false MemoryEnabled toggles framework memory persistence.
harness.memory.provider string no multiuser_memory Provider selects the memory provider plugin. Two ship in the agent image: “multiuser_memory” — the default, for small or personal deployments — keeps a per-user Markdown file inside the pod and needs nothing else running, at the price of loading the whole store into the model’s context on every turn, and “kube_agents_memory” — for enterprise deployments — gives ranked recall backed by the in-cluster Hindsight service and its Postgres database. Any other plugin Hermes ships may be named here too.
harness.memory.userProfileEnabled boolean no false UserProfileEnabled toggles per-user memory profiling.
harness.eventWatcher object no EventWatcher configures cluster event ingestion — the k8s-event-watcher that turns cluster warnings into autonomous triage sessions. Its enabled: false is the emergency stop for an event storm.
harness.eventWatcher.enabled boolean no true Enabled controls whether the watcher is started at all. Absent means started: the watcher is how a fleet notices its own incidents, so only an explicit false turns it off.
harness.driftDetector object no DriftDetector configures out-of-band change detection — the drift-detector that reads GKE admin-activity audit records from a Pub/Sub subscription and turns the ones a person made outside git into triage cards. Off unless asked for, unlike EventWatcher above.
harness.driftDetector.enabled boolean no false Enabled controls whether the detector is started. Absent means not started, the opposite of EventWatcher, and the reason is a dependency rather than caution: the detector reads a Pub/Sub subscription that exists only where the drift-pubsub Terraform module was applied. An install without one that started the detector anyway would get a process that never exits and never reports a change — the subscription is not checked at startup, and a pull that fails because it does not exist is retried for the life of the pod. The pod stays Ready, so an install left on by accident is indistinguishable from a fleet nobody has touched.
harness.driftDetector.subscription string no Subscription is the Pub/Sub subscription carrying the audit records. Empty takes the detector’s own default, which is the name the drift-pubsub module creates; set it only for a subscription made by hand or renamed.
harness.driftDetector.gitopsManagers string no GitopsManagers names the managedFields managers that are the GitOps controller — argocd-controller, flux. Comma-separated and matched exactly.
harness.stallWatch object no StallWatch tunes the controller stall watch — the stall-watch cron job on the Platform Agent’s roster that sweeps the fleet for controllers that stopped making progress and raises an alert for each new stall. Absent keeps the watch’s built-in behaviour.
harness.stallWatch.excludeNamespaces []string no max items 100; items max length 63; items pattern ^[a-z0-9]([-a-z0-9]*[a-z0-9])?$ ExcludeNamespaces names namespaces the watch never reads, on every cluster, in addition to the system namespaces it always skips. Matched exactly. An open alert in a namespace added here is closed with a note that the namespace was excluded.
harness.stallWatch.minStallAgeMinutes integer no min 0; max 1440 MinStallAgeMinutes holds a new alert until one of the namespace’s stalls has lasted at least this long. The age is the longer of what stall_report.py measures on the object and how long the watch has seen it. A stall that is younger stays in the watch’s ledger and is checked again on each run; an object that joins a namespace with an open alert is not held. Absent or 0 alerts on the first run that sees the stall.
harness.stallWatch.kinds []string no max items 20; items max length 253; items pattern ^[a-z0-9]([-a-z0-9]*[a-z0-9])?(\.[a-z0-9]([-a-z0-9]*[a-z0-9])?)*$ Kinds replaces the watch’s default list of resources to scan (Deployments, StatefulSets, DaemonSets, Jobs, Gateway API Gateways and HTTPRoutes, and cert-manager Certificates). Each item is a kubectl resource name such as deployments or gateways.gateway.networking.k8s.io. The single item all scans every namespaced kind the cluster serves, one read per kind per namespace, which is slow on a large fleet. Absent or empty keeps the default list. Secrets, ConfigMaps, Events, Endpoints, EndpointSlices, ControllerRevisions and Leases are refused: the scan reports nothing from them, and a Secret listing would carry every body.
harness.tuning object no Tuning sets per-persona execution limits. Unset values keep the defaults baked into the agent image.
harness.tuning.default object no Default applies to the default profile — the Chat Agent front door. Delivered as a config overlay merged into that profile at pod startup, like the others.
harness.tuning.default.apiMaxRetries integer no min 1; max 100 APIMaxRetries is how many times a failed model call is retried before the run gives up. Hermes defaults to 3, which suits an interactive session where a human can retry; a background worker has nobody to retry it, so a transient burst of upstream 429s or 503s ends the run.
harness.tuning.default.maxTurns integer no min 1; max 1000 MaxTurns is how many iterations (model calls) a single turn may take. Hermes defaults to 90. A long multi-step task can exhaust it while still mid-flight, and a run that does cannot even produce a closing summary. Repository exploration is the main consumer, so size this against how much the agent has to read, not against how complex the request is.
harness.tuning.platform object no Platform applies to the platform profile (the Platform Agent). Delivered as a config overlay merged into that profile at pod startup.
harness.tuning.platform.apiMaxRetries integer no min 1; max 100 APIMaxRetries is how many times a failed model call is retried before the run gives up. harness.tuning.cluster object no Cluster applies to every cluster-* profile (the Cluster Agents). Delivered as a single class overlay, merged into each existing cluster profile at pod startup and into a new one when it is scaffolded — onboarding a cluster does not roll the pod, so a profile created between two starts has to pick the overlay up itself.
harness.tuning.cluster.apiMaxRetries integer no min 1; max 100 APIMaxRetries is how many times a failed model call is retried before the run gives up. Hermes defaults to 3, which suits an interactive session where a human can retry; a background worker has nobody to retry it, so a transient burst of upstream 429s or 503s ends the run.
harness.tuning.cluster.maxTurns integer no min 1; max 1000 MaxTurns is how many iterations (model calls) a single turn may take. Hermes defaults to 90. A long multi-step task can exhaust it while still mid-flight, and a run that does cannot even produce a closing summary. Repository exploration is the main consumer, so size this against how much the agent has to read, not against how complex the request is.
harness.tuning.maxInProgress integer no min 1 MaxInProgress caps how many kanban workers run concurrently across the whole board. It is board-wide rather than per-persona: there is one dispatcher, and every worker it spawns — platform and cluster alike — draws on the same model quota. Setting it to 1 serialises all delegated work.
harness.tuning.maxSessions integer no min 1; max 10000 MaxSessions caps how many A2A session pods run concurrently, install-wide. It only means something under mode: next - a today install renders neither the gateway that spawns session pods nor this bound. “Delegate:” makes pod creation user-triggerable from chat and threads are free, so the principal map bounds WHO can spawn and this bounds HOW MANY.

harness.tuning.profiles.ceiling integer no min 1; max 1000 Ceiling is the most profile tasks running at once across every profile on the install. The dispatcher enforces it, reserving max(1, ceil(Ceiling/3)) of it for interactive tiers so unattended work can’t starve people, and the profile namespace’s pod quota is derived from it. Absent means DefaultProfileCeiling.

Moves LastActiveTime: a refused command is still the agent at work.
usage.brokerFailuresTotal integer no BrokerFailuresTotal is the cumulative count of brokered work the credential broker took on and could not carry out for a reason that is its own or its upstream’s: a command that ran past its deadline (exit 124), a broker fault on the exec route (a 500), a git failure on the version-control route (a 500 or 502), a failed forge token mint (a 502), or any 5xx on the Cloud API, MCP and watcher relays, whose upstream status passes through. A command’s own non-zero exit is not one (that is ToolExecutionsTotal’s error outcome), nor is a policy refusal or the broker’s own busy (a 403 or 503; the version-control route’s 503 for an unreadable managed-repository list is a fault and does count), nor a chat or Slack post the forge refused for the caller’s channel or scope; the broker’s own chat event pull failing, its Pub/Sub subscription or its credential to it, does count. Read from the broker’s kubeagents_broker_execution_failures_total, summed over its kind and tool labels, every five minutes and kept monotonic the same way as ToolExecutionsTotal; a timed-out command counts here and as an error there. A rising share of this against ToolExecutionsTotal says the broker, its credentials or its upstreams are failing, where a policy refusal is the tool counter’s blocked outcome in Prometheus. Does not move LastActiveTime: a watcher retrying an unreachable fleet cluster through the relay is not the agent at work.
usage.chatTurnsErroredTotal integer no ChatTurnsErroredTotal is the cumulative count of synchronous chat turns the gateway failed to complete: on the Hermes gateway, an exception out of the turn, a result the agent marked failed (a provider 429 or 5xx, a connection error, the gateway timeout) or a provider authentication failure, counted by the chat_metrics plugin’s kubeagents_chat_turns_errored_total on the gateway pod that runs Hermes; and on a next-mode install, an A2A task that ended failed or rejected, read from the A2A gateway’s kubeagents_a2a_gateway_task_terminals_total under those two states. That family carries no platform, so on next it counts every A2A task’s terminal, a door’s program-to-program task included, not chat alone; rejected is a task the executor refused, counted as the design asks. Read every five minutes and kept monotonic the same way as ToolExecutionsTotal. Does not move LastActiveTime: the message that started the turn already did.
usage.backgroundTasksGaveUpTotal integer no BackgroundTasksGaveUpTotal is the cumulative count of background cards on the agent’s board whose breaker tripped: cards that exhausted their attempts and gave up, whether a cluster event or a chat ask started them. Hermes parks such a card as blocked and records a gave_up event against it, and that event is what is counted, once per card. Read every five minutes from the chat_metrics plugin’s kubeagents_kanban_tasks_gave_up_total on the gateway pod that runs Hermes, which reads the board at scrape time and counts the cards that gave up since its listener started (the ones that had already given up are its baseline, so a restart adds nothing twice; a card that gives up while the gateway restarts is missed, an under-count); kept monotonic the same way as ToolExecutionsTotal. Does not move LastActiveTime: a card giving up is not the agent at work.
usage.negativeFeedbackTotal integer no NegativeFeedbackTotal is the cumulative count of thumbs-down reactions put on one of the bot’s Slack messages: the chat_feedback_reactions hook on the Hermes gateway counts a -1 or thumbsdown reaction, skin tone or not, whose reactor is not the bot and whose message is the bot’s, once per reactor and message within one gateway process (a thumbs-down taken off and put back is one; after a restart the same one counts again, and a reaction before the first inbound message after a start is not counted), into the chat_metrics plugin’s kubeagents_chat_feedback_negative_total, which is read every five minutes and kept monotonic the same way as ToolExecutionsTotal. Slack through the Hermes gateway only: Google Chat delivers no reaction events, and the A2A gateway’s Slack adapter does not subscribe to them, so on a next-mode install with Slack through A2A this stays at 0. Does not move LastActiveTime: the message the person reacted to already did.
usage.remediationsClosedUnmergedTotal integer no RemediationsClosedUnmergedTotal is the cumulative count of proposals this install opened that the forge reported closed without a merge, by a person, a forge rule or a bot; a close the broker made itself, the fleet audit tidying a stale proposal, is not counted. The broker counts each once per broker process when one of its own reads, proposal-list or proposal-view, shows it closed, under the rules RemediationsMergedTotal uses: the author is the credential’s login, the close is not before the process started, each proposal once. Read from the broker’s kubeagents_vcs_proposals_closed_unmerged_total every five minutes and kept monotonic the same way as ToolExecutionsTotal. A close no read shows is not counted, so it under-counts; a proposal closed, reopened and merged counts here and in RemediationsMergedTotal once each. A high share of this against RemediationsMergedTotal says the agent’s proposals are being rejected. Does not move LastActiveTime: a close is not the agent at work.
usage.clustersRegistered integer no ClustersRegistered is the number of clusters the event watcher built a client for at its last start: the management cluster and the Cluster Agent profiles the GKE API would describe, the management cluster counted once even where a profile also covers it. Read every five minutes as the number of k8s_event_watcher_cluster_up series the watcher exports, the largest reading across gateway replicas. The watcher discovers its fleet once per process, so a cluster that joins or leaves is counted after the gateway pod restarts, not before. A gauge, not a counter: it falls after such a restart. Absent when the operator has no current reading: before the first poll, while the event watcher is disabled, and after two polls in a row in which no gateway replica could be read, whether its listener failed, its pod was not running, or the operator could not reach it; the CR’s events and the gateway pod’s state say which. A 0 is a reading: the watcher answered and exports no series.
usage.clustersMonitored integer no ClustersMonitored is how many of ClustersRegistered are delivering events: the k8s_event_watcher_cluster_up series at 1, whose informer has completed its initial list. The difference from ClustersRegistered is the number of clusters silently unwatched, a stuck informer, a 403 on the events list, or a stopped one. A 0 is a reading, and the normal one while the watcher starts, so read a fall alongside the pod’s age. Absent on the same terms as ClustersRegistered: one poll in which no gateway replica could be read leaves both where they were, and a second in a row clears both, because the operator then has no current reading and an absent field says so.
usage.activeInterfaces []string no ActiveInterfaces lists the communication channels the spec enables, sorted: “dashboard” unless spec.harness.hermes.dashboardEnabled is false, and “googlechat”, “slack” and “teams” for each spec.integration entry whose enabled is true. Resolved on every reconcile and written by the Ready status update when it changes; a pass that parks the CR Degraded leaves the previous value, so read it alongside the Ready condition, as networkPolicy.generated is read. Absent while the served CRD predates it.
usage.lastActiveTime metav1.Time no LastActiveTime is the time of the last poll in which a counter above moved: a brokered command ran or was refused, a proposal was opened or merged, a chat message reached the gateway, or an event was accepted for triage; BrokerFailuresTotal, ChatTurnsErroredTotal, BackgroundTasksGaveUpTotal, NegativeFeedbackTotal and RemediationsClosedUnmergedTotal alone leave it where it was. Scheduled maintenance jobs that run brokered commands move it too – the Controller Stall Watch cron runs some every 30 minutes by default – so it marks agent activity of any origin, not human or operator use alone; LastHumanActiveTime is the one that does. Advances at most once per five minutes.
usage.lastHumanActiveTime metav1.Time no LastHumanActiveTime is the time of the last poll in which the one counter only a person moves advanced: ChatMessagesInboundTotal, a chat message that reached the gateway, counted before the sender allowlist, so an unlisted sender is still a person. Nothing else moves it. Brokered commands and accepted events come from the stall-watch cron and the event watcher on their own, proposals from the fleet audits, which open them with nobody asking, and a merge or a close can be a forge rule or a bot; all of those move LastActiveTime and leave this alone, so an install nobody has talked to in a month shows it. Absent until a person has sent a message since the operator that writes it started. Advances at most once per five minutes.
